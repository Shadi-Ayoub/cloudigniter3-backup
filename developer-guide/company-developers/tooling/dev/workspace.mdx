Use Node 22.14 or newer and the pnpm version pinned in the workspace's `package.json`.
Install the private workspace dependencies with `pnpm install`. DEV maintenance
checks for a pnpm workspace named `cloudigniter` and its `@cloudigniter/dev` package.
This guard prevents accidental use in a consumer project; GitHub and npm enforce
their own authorization.

## GitHub CLI setup

The DEV install hook reuses a compatible GitHub CLI (`gh`) from the machine or
installs a pinned, checksum-verified copy in the current user’s cache. It needs no
administrator access. Package managers can block dependency install scripts;
[dev github setup](/commands/dev/github-setup) explains script approval, manual
recovery, supported platforms and cache configuration.

GitHub login is a separate step. Local package builds and checks remain available
when GitHub CLI setup is skipped or cannot complete. Install Git separately for
repository operations.

## Select the working directory

Package operations run from the exact `packages/<name>` directory. From the
workspace root, pnpm can select that directory for you:

```bash
pnpm --filter @cloudigniter/next exec dev package check
```

The workspace root, an application directory and nested source folders are refused
as package targets. A workspace-discovery override does not change the invoking
package or its current directory. The [dev command overview](/commands/dev)
explains invocation and common options; each command manual specifies its scope.

Ordinary maintenance does not require release-policy configuration or GitHub login.
For online company operations, configure [profiles and repositories](/company-developers/tooling/github-npm-publishing)
before following the relevant delivery workflow.

`pnpm exec dev` invokes the toolkit. `pnpm dev` selects a package script, which
starts JavaScript watch mode in platform packages. Existing aliases are mapped in
[Package script compatibility](./package-scripts.mdx).

## Migrating from ci-dev

The former `ci-dev` executable and its build exports have been removed from the
public CLI package. Install or link `@cloudigniter/dev` as a development dependency
and replace `ci-dev` with `dev` in maintainer scripts. Consult the
[dev command manuals](/commands/dev) for supported command paths and options.
The older `cloudigniter` and `cloudigniter-dev` executable names are also retired;
there are no legacy aliases.

Change build imports from `@cloudigniter/cli/tooling/tsup`, `/tooling/entries` and
`/tooling/inject-use-client` to the same subpaths under `@cloudigniter/dev`.
Build configuration types are available from `@cloudigniter/dev/types`.
Consumers of the tsup configuration install its `tsup` and `esbuild` build peers.
Application `ci` commands retain their existing API.

Keep package-local quality gates enabled and complete script invocations
non-interactive. Build imports belong in development configuration; they must not
enter application runtime imports. See [DEV architecture](./architecture.mdx)
for the package dependency boundary.
