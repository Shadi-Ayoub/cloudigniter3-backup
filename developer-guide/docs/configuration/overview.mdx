# Configure your application

Start with the complete `cloudigniter.config.ts` supplied by the template. It satisfies `CiNextCoreConfig` from
`@cloudigniter/next/types`. Adjust the relevant block while retaining the other required application wiring.

| Concern | Configuration or workflow |
| --- | --- |
| Login and access-control policy | [`auth`](/docs/core-system/configurations/cloudigniter.config.ts) |
| Route registration, sign-in requirements, and permissions | [Routes configuration](/docs/configuration/routes) |
| Tenant selection and public URL structure | [Routing modes](/docs/core-system/multi-Tenancy/configuration/routing-modes) |
| Next.js, browser, and backend runtime mode | [Environment modes](/docs/environment-modes/intro) |
| Languages, messages, and direction | [Localization](/docs/configuration/localization) |
| Theme selection and application CSS | [Themes and styling](/docs/configuration/themes) |
| Values consumed by the running application | [Settings](/docs/configuration/settings) |
| Provider credentials and generated resources | [Data and providers](/docs/data/overview) |

The file-level configuration and resolved runtime settings have different roles. Do not assume editing a
registry persists a value or changing a public environment variable grants access. Verify the consuming
server path and the effective context for the running application.

## Work through the configuration chapter

First register your [application routes](/docs/configuration/routes) and align environment modes across the
Next.js application and backend. Then configure localization,
presentation, and settings resolution.

## How configuration is resolved

Finish the chapter with [How configuration is resolved](/docs/configuration/resolution). Follow the configured
inputs and generated Amplify outputs through proxy routing, language resolution, bootstrap, and the providers
that apply them. The section explains where to find effective values in the application context and which
source takes precedence when values overlap.

Afterward, continue with [Authentication and identity](/docs/identity/authentication) before enabling protected
business features.
