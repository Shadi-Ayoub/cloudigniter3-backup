---
title: Best practices
description: Safety rules for environment modes and developer-only operations.
sidebar_position: 6
---

- Keep Next.js and Amplify `CI_ENV_MODE` values aligned.
- Use separate cloud resources for development, test, staging, and production.
- Require `development` mode, authentication, and exact `developer` membership together.
- Repeat the check in every server action and provider handler; UI visibility is not authorization.
- Use exact canonical role IDs. `DEVELOPER` is not the same identifier as `developer`.
- Store seed provenance and garbage-collection markers atomically with created resources.
- Use bounded `GetItem`/`Query`/transaction access patterns and least-privilege handler IAM.
- Preserve records when provenance, protection, or ownership checks do not match.
- Never give a workstation direct table permissions just to make a seeder convenient.
- Never enable development tools in `test`, `staging`, or `production`.
