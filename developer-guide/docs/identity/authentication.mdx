# Authentication and identity

Authentication establishes who is making a request. Authorization decides whether that actor can perform a
particular operation on a resource in a particular scope. Learn both before adding protected data features.

## Use the configured identity provider

The reference application uses Amplify and Cognito. `cloudigniter.config.ts` configures the login route and
authentication UI; provider-specific inputs belong under the provider configuration. The server bootstrap
resolves the current user and roles for its context.

Customize the login page using `src/custom/authenticator`: its exported hooks include the login shell,
Authenticator props, and token-based theme override. Keep authentication/session checks in the configured
server integration; visual customization does not replace those checks.

## Protect a route and its operations

Set `protected: true` on a custom logical route when it requires sign-in. Add its actual permission requirements
through the access-control catalog and route authorization contract. A protected page alone does not protect
an independent Server Action, API endpoint, or provider mutation.

The application-owned access-control extension lives in `src/custom/auth/app-access-control.ts`.
`src/custom/auth/app-authorizer.ts` compiles the resolved catalog with the configured policy. Generic helpers
and public types come from `@cloudigniter/core/lib` and `@cloudigniter/core/types`.
