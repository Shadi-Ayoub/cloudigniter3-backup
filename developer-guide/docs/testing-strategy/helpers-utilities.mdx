title: Testing helpers and seeders
description: Use current CloudIgniter gates, key builders, fixture loaders, and garbage collectors.

Use these supported APIs instead of environment-suffixed keys or table scans:

| Need | API |
| --- | --- |
| Gate a deployed developer capability | `ciCanAccessDeveloperTools()` from `@cloudigniter/core/lib` |
| Resolve server environment mode in Next.js | `ciGetEnvMode()` from `@cloudigniter/next/server` |
| Build CloudIgniter table keys | `ciBuildTableKey()` / `ciBuildTableKeys()` from `@cloudigniter/core/lib` |
| Load application fixture JSON | `ciReadJsonSeederData()` from `@cloudigniter/core/server` |

`assertNotLive()`, `scopePkWithEnv()`, and `cleanupEnvironment()` are not current public CloudIgniter APIs. Do not
recreate those legacy patterns. A generic scan or suffix-based batch delete can cross capability, tenant, or
ownership boundaries.

Each seeder needs explicit provenance and a bounded garbage-collection access pattern. Tenant seeders write one
marker per tenant into the seeder's base-table partition and clean up through a strongly consistent `Query` plus
conditional transactions. Cross-service seeders require an idempotent operation that records each participant's
progress.
