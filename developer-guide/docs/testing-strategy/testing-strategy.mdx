CloudIgniter testing follows four rules:

1. Use separate deployments/resources for development, test, staging, and production.
2. Exercise the same canonical key builders, authorization, provider adapters, and bounded access patterns in
   every environment.
3. Treat test data as owned resources with explicit provenance and deterministic garbage collection.
4. Keep interactive developer tools stricter than tests: `development` mode, authenticated actor, exact
   `developer` role, and repeated server/provider checks.

## Focused tests

Test pure gates, validators, key builders, fixture parsing, authorization, and error normalization without a cloud
dependency. For persistence adapters, test exact commands, keys, condition expressions, pagination, consistency,
and error translation. Handler tests must cover wrong environment, missing authentication, wrong role, and the
allowed path.

## Integration tests

Use a disposable deployment whose `CI_ENV_MODE` matches its purpose. Do not point development seeders at staging
or production. Seed through deployed handlers rather than granting test runners or developer profiles direct
table access.

## Cleanup tests

Verify same-seeder retries, non-owned ID collisions, fixture removal after seeding, orphan markers, ownership
drift, malformed markers, partial failure, pagination, and no-scan behavior. A successful test run is not complete
when it leaves untracked data behind.
