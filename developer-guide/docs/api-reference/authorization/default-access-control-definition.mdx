# CI_DEFAULT_ACCESS_CONTROL_DEFINITION

The runtime-frozen core catalog used as the first layer by `ciCreateAppAccessControl()`. Import it from
`@cloudigniter/core/lib` when you need to inspect, validate, or display the built-in policy.

```ts title="Core access-control definition" showLineNumbers
const CI_DEFAULT_ACCESS_CONTROL_DEFINITION: CiAccessControlDefinition;
```

It registers the `platform`, `identity`, and `developer` domains; dashboard, authorization, protected core
authorization, settings, tenants, users, and developer-tool resources; and these roles:

| Role                 | Precedence | Inherits       |
| -------------------- | ---------: | -------------- |
| `system-super-admin` |          0 | `system-admin` |
| `system-admin`       |         10 | `user`         |
| `super-admin`        |         20 | `admin`        |
| `admin`              |         30 | `user`         |
| `developer`          |         40 | `user`         |
| `user`               |         50 | —              |

The business-administration lane is `user → admin → super-admin`; the technical-administration lane is
`user → system-admin → system-super-admin`. `system-admin` intentionally receives no business-admin privileges
through inheritance. Assign roles from both lanes when one subject needs both responsibilities.

Lower precedence numbers are stronger, but precedence does not imply inheritance. A system assignment remains
system-only. Assign a compatible role at global scope with `descendants` when it must reach every tenant and Org
Unit.

Every built-in privilege includes a stable ID and a human-readable title. Administration interfaces display the
title while persistence and authorization evidence continue to use the ID.

`platform.authorization.core.override` is a sensitive, system-only capability. The core override helper also
requires the matching access to come from a direct `system-super-admin` assignment, so another role or direct
privilege cannot opt itself into core modification.

```ts title="Inspect the core catalog" showLineNumbers
import {
  CI_DEFAULT_ACCESS_CONTROL_DEFINITION,
  ciCreateAuthorizer,
} from "@cloudigniter/core/lib";

const authorizer = ciCreateAuthorizer(CI_DEFAULT_ACCESS_CONTROL_DEFINITION);
```

The object and its nested collections are frozen. Use
[`ciCreateAppAccessControl()`](./ci-create-app-access-control) for application-owned additions. Core changes
must use an audited override created by a directly assigned `system-super-admin`.
