# CiDevBeacon

`CiDevBeacon` is a [Server Component](/dictionary/s#server-component) exported from
`@cloudigniter/next/server`. It applies the environment visibility rule and renders the interactive
[Dev Beacon](/dictionary/d#dev-beacon) client surface with serializable configuration.

```tsx
import { CI_DEV_BEACON_LOGO } from "@cloudigniter/core/lib";
import { CiDevBeacon } from "@cloudigniter/next/server";

<CiDevBeacon
  context={context}
  position="bottom-right"
  visibleWhenEnv="development"
  defaultTab="status"
  logo={CI_DEV_BEACON_LOGO}
/>;
```

The `position` value selects the initial placement. After rendering, users can drag the button with a mouse,
touch, or pen to any location that keeps the control within the viewport. Movement beyond the 4-pixel activation
threshold suppresses the following click, so releasing a drag does not open the dashboard. A normal click,
**Enter**, or **Space** opens it.

Keyboard users can press **Alt + Arrow key** while the button is focused to move it by 8 pixels, or add **Shift**
to move it by 32 pixels. The custom location is client-session state: a reload, remount, or new `position` prop
restores the selected preset. Viewport resizing clamps a custom location so the button remains available.

## Org Unit resolution report

Both the Tenant and Org Unit checkup dialogs offer **View JSON Report**. It opens a read-only JSON view of the
selected area, its summary, and every test, including probe paths, messages, states, and complete expected/actual
values. Unavailable expected or actual values appear as `null`. **Copy JSON** copies the entire displayed report
with indentation and confirms success; if clipboard access fails, the JSON remains selectable for manual copying.
**View Test Results** returns to the test cards.

The resolution checkup exercises the configured internal lookup endpoint with five reserved scenarios: active
root, deep active, missing, suspended, and archived [Org Unit](/dictionary/o#org-unit). In the template, the
reserved probe tenant resolves from built-in fixtures only after the trusted developer-access check succeeds.
Ordinary tenant/path lookups remain provider-backed. The resolver forwards the session cookie to the same-origin
lookup and refuses redirects; lookup responses use `Cache-Control: no-store`.

See [Check Org Unit resolution](../../environment-modes/development-tools-and-seeding#check-org-unit-resolution)
for expected results and troubleshooting.

## Props

`CiDevBeacon` accepts `CiDevBeaconProps<CiNextContext>` from `@cloudigniter/core/types`.

| Prop                   | Type                            | Default               | Behavior                                                                                                                                                           |
| ---------------------- | ------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `context`              | `CiNextContext`                 | required              | Supplies resolved environment, configuration, authentication, and diagnostic context.                                                                              |
| `position`             | `CiDevBeaconPosition`           | `"bottom-right"`      | Selects the initial button preset. Dragging does not mutate this prop.                                                                                             |
| `visibleWhenEnv`       | `CiEnvMode \| null`             | `"development"`       | Renders only in the matching environment; `null` skips this component-level environment comparison. The trusted developer-access gate still belongs at the caller. |
| `defaultTab`           | `CiDevBeaconTabValue \| string` | `"status"`            | Selects the tab shown when the dashboard opens.                                                                                                                    |
| `logo`                 | `CiDevBeaconLogoSpec`           | `{ kind: "default" }` | Provides a server-serializable logo specification.                                                                                                                 |
| `extraTabSpecs`        | `CiDevBeaconExtraTabSpec[]`     | `[]`                  | Adds supported serializable dashboard tab specifications.                                                                                                          |
| `viewportTopOffset`    | `string`                        | `"120px"`             | Initial top offset for the open dashboard surface before client measurement.                                                                                       |
| `viewportBottomOffset` | `string`                        | `"0px"`               | Initial bottom offset for the open dashboard surface before client measurement.                                                                                    |

The supported initial positions are `top-left`, `top-middle`, `top-right`, `left-middle`, `right-middle`,
`bottom-left`, `bottom-middle`, and `bottom-right`.

`CiDevBeaconClient` is also exported from `@cloudigniter/next/client` for framework composition that already owns a
resolved client-safe context. Prefer `CiDevBeacon` when rendering from the normal CloudIgniter root wrapper because
it preserves the [Server Component](/dictionary/s#server-component) visibility and serialization boundary.

See [Development tools and application seeding](../../environment-modes/development-tools-and-seeding) for the
developer-access rule and task-oriented usage.
