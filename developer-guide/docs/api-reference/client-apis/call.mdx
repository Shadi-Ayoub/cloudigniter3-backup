# ciCall

Import the helper from `@cloudigniter/core/lib` and its public types from `@cloudigniter/core/types`.
It is commonly used by client interactions and uses the available `fetch` implementation.

```ts
import { ciCall } from "@cloudigniter/core/lib";
import type { CiCallOptions, CiCallResult, CiRequest, CiResponse } from "@cloudigniter/core/types";

```

```ts title="Signature"
declare function ciCall<TInput, TBody = unknown>(
  url: string,
  request: CiRequest<TInput>,
  options?: CiCallOptions,
): Promise<CiCallResult<TBody>>;
```

## Request and transport

`CiRequest` requires `input` and accepts optional `envMode`, `authMode`, provider `options`, and `critical`.
The helper serializes that envelope as JSON, defaults to POST, and supplies `Content-Type: application/json`.
A supplied `envMode` is retained; otherwise it uses `NEXT_PUBLIC_CI_ENV_MODE`, falling back to `test`.
The server must independently validate its trusted mode, actor, scope, and permission.

| Option | Behavior |
| --- | --- |
| `method` | GET, POST, PUT, PATCH, or DELETE; defaults to POST. The current implementation always sends a body, so use a body-compatible method. |
| `headers` | Additional headers; supplied values override defaults. |
| `signal` | Passes an AbortSignal to fetch. |
| `cache`, `credentials`, `mode`, `redirect`, `referrerPolicy` | Passed through to fetch. |

## Result

A successful transport result has `ok: true`, `kind: "OK"`, `httpStatus`, and `response: CiResponse<TBody>`.
A failure has `ok: false`, `kind`, `message`, and `httpStatus` (null before an HTTP response), with an optional
response and cause.

| Failure kind | Trigger |
| --- | --- |
| `NETWORK_ERROR` | Fetch throws, including cancellation or a request rejected by the fetch runtime. |
| `NON_JSON_RESPONSE` | The response has no JSON content type or its JSON cannot be parsed. |
| `HTTP_ERROR` | HTTP response status is not successful. |
| `CI_ERROR` | HTTP succeeds but the envelope's `statusCode` is at least 400. |

`CiResponse` is the application envelope with `ok`, `statusCode`, and `body`, plus response metadata.
The helper classifies failures using the HTTP response and `statusCode`; it does not perform full runtime schema
validation. Endpoints must return the agreed envelope. `critical` is forwarded in the request and does not make
this helper throw instead of returning a classified result.

## Example

This example assumes the application implements `/api/notes`:

```ts
const result = await ciCall<{ title: string }, { id: string }>(
  "/api/notes",
  { input: { title: "First note" } },
);

if (!result.ok) {
  console.error(result.kind, result.message);
} else if (result.response.ok) {
  console.log(result.response.body.id);
}
```

This replaces the previous unprefixed `call()` examples. For the full application workflow, see
[API calls, errors, and feedback](/docs/building-features/api-and-feedback).
