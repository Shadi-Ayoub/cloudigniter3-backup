# Tenants and Org Units

A Tenant identifies an organization boundary in the application. An Org Unit describes a node in an
organizational tree and can be attached to more than one Tenant. Scope determines the context of an operation;
authorization determines whether the current actor may perform it.

## Work through the chapter

1. Read [Core Tenant concepts](./core-concepts) to distinguish identity, slug, status, and organizational structure.
2. Learn the [system, global, and tenant scopes](./core-concepts/tenant-scope).
3. Configure [routing modes](./configuration/routing-modes) and build [public navigation links](./client-side).
4. Manage [Org Unit trees and sharing](./org-unit-management).
5. Apply [Tenant status, Trash, and restoration](./lifecycle-operations).
6. Consult [control-plane storage](./ddb-table-structure) when you need the persistence model.

Environment isolation is separate from tenancy. A Tenant is not a substitute for an isolated development
backend. Similarly, selecting a Tenant in the URL does not establish membership or permission to access its data.
