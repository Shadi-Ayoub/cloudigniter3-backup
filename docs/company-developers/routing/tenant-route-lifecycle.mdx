# Tenant route lifecycle

Tenant-aware routing crosses the generic route contract, Next.js [proxy](/dictionary/p#proxy) runtime,
and template filesystem routes:

```text
packages/core CiRouteDefinition
  → packages/next proxy Tenant resolution and scope enforcement
  → apps/templates/cloudigniter-next-aws-v1/src/kernel/server/routes.ts composes logical registrations
  → (ci-global)/ci-global or (ci-tenant)/ci-tenant physical page
```

## Ownership

| Concern                                         | Owner           |
| ----------------------------------------------- | --------------- |
| `tenantScopes` contract and public-path builder | `packages/core` |
| [Proxy](/dictionary/p#proxy) enforcement and internal rewrite | `packages/next` |
| Logical route registry and physical page entry  | `apps/templates/cloudigniter-next-aws-v1` |

The [proxy](/dictionary/p#proxy) resolves Tenant and Org Unit context before matching the logical
`featurePathname`. After a route match, it checks the optional
`tenantScopes` list before authentication. A mismatch produces an unresolved
route-information response with reason `route-tenant-scope-not-allowed`; it
must not construct a resolved route context or render the wrong physical tree.

Omitting `tenantScopes` intentionally preserves existing behavior. A present
empty array denies every scope. This allows applications to introduce explicit
scope declarations incrementally.

## Authentication service failures

`packages/next` owns both the session decision in `ciHandleRouteLogic()` and its HTTP response in
`ciNextProxyResponse()`. The session request forwards the caller's cookies to
`POST /ci-internal/auth/session` with caching disabled and redirects rejected.

- `401` establishes a signed-out decision.
- A successful JSON response must contain a boolean `authenticated` field.
- Network failures, other unsuccessful statuses, or invalid response bodies produce the internal
  `auth-unavailable` decision. The proxy returns `503` with `Cache-Control: no-store` and `Retry-After: 5`.
  It does not redirect, rewrite, or persist resolved route context for this failure.
- Public pages other than `/login` do not depend on this session check.

Never collapse an unavailable service into sign-out: a browser can retain its authenticated Amplify
state while the server endpoint fails, leaving Authenticator hidden after a misleading login redirect.
Cover the protected settings path, authenticated return navigation, genuine sign-out, and service
failures in the proxy regression tests. Check actual endpoint routing as well: unit tests with a mocked
session response cannot detect a missing Next.js development route registration.

## Physical routing invariants

- Route registry keys never include `/ci-global` or `/ci-tenant`.
- Browser links never target those internal prefixes.
- `(ci-global)` and `(ci-tenant)` are URL-less route groups.
- Their nested literal directories are required [proxy](/dictionary/p#proxy) rewrite targets.
- Scoped layouts call `appBootstrap()` and pass `context` to `CiLayout`.
- Scoped pages call the cached `appBootstrap()` and pass `context` to `CiPage`.
- Pages beneath a `CiLayout` do not add another `CiPageWrapper`.

When adding or changing this lifecycle, validate the core route types and
serialization guard, the focused [proxy](/dictionary/p#proxy) scope tests, both package typechecks,
and the template consumer. See the user guide's
[Routing modes](/docs/core-system/multi-Tenancy/configuration/routing-modes)
and the API reference for
[`CiRouteDefinition`](/docs/api-reference/type-definitions/CiRouteDefinition).

## Root-domain normalization

The Next tenant adapter accepts bare hosts, host-and-port pairs such as `localhost:3000`, and HTTP(S) URLs in `rootDomains`. Normalize bare values with an explicit scheme before URL parsing, then remove the port and lowercase the host. A domain match requires the exact root or a dot-delimited subdomain; a lookalike suffix must not select a tenant. The routing contract tests cover these cases.
