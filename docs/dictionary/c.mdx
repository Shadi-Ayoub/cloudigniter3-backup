# C


## Canonical Org Unit

The single authoritative Org Unit record whose identity can be shared by several tenants. Tenant/path attachments point to this record instead of duplicating the node for each tenant.


## CiDataTable

CloudIgniter’s reusable management-table component, with consistent sorting, filtering, responsive formats, actions, feedback, accessibility, and provider-backed data behavior. Its default sort is newest creation date first. See [Data table](/docs/ui-components/data-table).


## Claim

In authentication, a claim is a statement about an identity carried in a token, such as a user ID, email verification status, or group membership. Token claims are not specific to AWS; CloudIgniter's AWS integration reads them from the provider session. Claims supply identity information; a claimed role or group does not by itself establish permission in a particular Tenant.

## CI {#continuous-integration}

Continuous Integration: automatically building and testing integrated code changes to detect failures early. In this guide, **CI always means Continuous Integration**; the platform is named **CloudIgniter**. The lowercase `ci` executable is the [CloudIgniter CLI](/dictionary/c#cloudigniter-cli), a separate name. See [GitHub's introduction to Continuous Integration](https://docs.github.com/en/actions/get-started/continuous-integration).

## CI/CD {#continuous-delivery}

Continuous Integration combined with Continuous Delivery or Continuous Deployment. Delivery prepares validated changes for release and can retain an explicit approval gate; deployment automates release to an environment. Passing CI checks does not itself authorize npm publication or production deployment. See [GitHub Actions concepts](https://docs.github.com/en/actions/get-started/understand-github-actions) and [CloudIgniter's delivery strategy](/company-developers/publishing/strategy/release-and-delivery).


## Client Component

A React component that executes in the browser and may own state, effects, events, and browser APIs. CloudIgniter keeps provider clients, credentials, filesystem APIs, and other server-only values outside this boundary.


## CloudIgniter

A reusable application platform composed of provider-neutral public APIs, internal capabilities, framework integrations, provider implementations, shared UI, CLI tooling, and a reference application template. Start with [Architecture and concepts](/docs/architecture/overview).


## CloudIgniter CLI

The public `@cloudigniter/cli` package, exposed through the `ci` executable for application resource, module, and supported provider operations. Application developers use it to build and operate applications. See [CloudIgniter CLI](/docs/cli/overview).


## CloudIgniter Core

The `@cloudigniter/core` package, which owns stable provider- and framework-neutral public contracts, types, and helpers. Generic public EmberGuard APIs are also exposed through this facade.


## Cognito

Amazon Cognito, the AWS service that manages user accounts, sign-in, account recovery, and identity groups for CloudIgniter's Next.js + AWS template. It is the template's [identity provider](/dictionary/i#identity-provider). [Amplify](/dictionary/a#amplify) libraries connect the application to Cognito, and CloudIgniter adapts the returned identity information into its current-user and authorization contracts. See [Authentication and identity](/docs/identity/authentication).


## Combining Algorithm

The rule used when several applicable privileges disagree. CloudIgniter defaults to `deny-overrides`; `highest-precedence` is available when the strongest assigned responsibility is intentionally authoritative.


## Current User

The identity resolved for the current request from the configured authentication session. In the CloudIgniter Next.js template, `appBootstrap()` exposes it as `context.auth.user`, with an ID, authentication state, role IDs, and available profile fields. An anonymous request has no user ID and is not authenticated. This identity still needs scoped assignments for permission checks. See [the resolved user example](/docs/identity/authentication#understand-the-resolved-current-user-and-roles).


## Custom Seam

An application-owned location that CloudIgniter upgrades preserve. Supported seams include `amplify/custom`, `src/custom`, and scoped `(ci-custom)` App Router trees; reusable platform code does not belong there.
