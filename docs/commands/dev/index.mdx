Use `dev` from the private `@cloudigniter/dev` toolkit for company package maintenance, GitHub operations, template delivery, Workspace convenience, and release requests. These commands are for CloudIgniter maintainers. Run `pnpm exec dev` with installed workspace dependencies; it prints help without a command. `pnpm dev` runs a package script and does not invoke this parser.

## Common options

| Option | Meaning |
| --- | --- |
| `--workspace-root=<path>` | Select workspace discovery; does not change the package working directory. |
| `--no-interactive` | Disable maintenance prompts. Release commands never prompt; browser login requires interaction. |
| `--verbose`, `-v` | Include diagnostic stack traces. |
| `--help`, `-h` | Show the complete executable help. |
| `--version` | Print the toolkit version. |

`--clear` applies to package, quality, Next, and module maintenance commands. `--json`, `--profile`, and `--dry-run` are accepted only where listed on the command page; maintenance workers do not require GitHub login. A GitHub profile can also come from `CLOUDIGNITER_PROFILE` for online operations. Use only the options supported by the selected command.

`dev start` and `dev open terminal` require the invoking directory to be inside the monorepo and reject `--workspace-root`. See [Workspace convenience](/company-developers/tooling/dev/workspace-tools).

`dev github setup` prepares the GitHub CLI executable and also works outside a workspace. It does not select or authenticate a company profile.

Package commands require the current directory to be `packages/<name>`. Use `pnpm --filter @cloudigniter/next exec dev package test` to select a package from the workspace root. Recipe steps such as `typecheck-tools`, `typecheck-tests`, and `test-coverage` are internal configuration names, not separate executable commands.

## Help and exit status

```bash
pnpm exec dev --help
pnpm exec dev --version
```

Exit code `0` indicates success, `1` an operational/validation failure, and `2` invalid usage or workspace/policy configuration. Cancelled maintenance prompts use `130`; child processes may preserve their own nonzero status.
