# Modules

Modules extend your application with features that have their own installation, configuration, and enablement
lifecycle. An optional module can contribute a dashboard page, settings, permissions, and backend resources.
CloudIgniter's fixed core capabilities remain part of the platform by default.

Start by managing a supplied module, then learn how to create a feature of your own:

| Lesson | What you will learn | Example |
| --- | --- | --- |
| [Optional modules](/docs/building-features/modules) | Detect, install, configure, enable, disable, and uninstall modules; understand their Amplify integration | The **To-Do List** module is included in the application template and starts **uninstalled** |
| [Creating your own modules](./creating-modules) | Build a manifest, dashboard page, settings, permissions, and AWS backend; generate, deploy, and install the feature | Create a **Personal note** module in your application's custom module folder |

Use modules for features that should be independently installed or disabled. For extensions that are always part
of your application, see [routes](./routes), [settings](./settings), [application configuration](./configuration),
and [user profiles](./user-profile).

Begin with [Optional modules](/docs/building-features/modules).
