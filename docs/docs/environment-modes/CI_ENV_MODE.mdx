For local development, keep the Next.js server, browser presentation, and Amplify handler environment aligned:

```env title="apps/templates/cloudigniter-next-aws-v1/.env.local"
CI_ENV_MODE=development
NEXT_PUBLIC_CI_ENV_MODE=development
```

```env title="apps/templates/cloudigniter-next-aws-v1/amplify/.env"
CI_ENV_MODE=development
```

CloudIgniter's backend manifest injects `CI_ENV_MODE` and `CI_REGION` into every active core handler. Application
handlers created outside that manifest must declare and validate their environment explicitly.

Server code reads the mode through trusted configuration or `ciGetEnvMode()`. A public variable is acceptable for
presentation hints, but client code cannot authorize developer tools or mutations. Server actions and provider
handlers resolve the trusted mode again.

Use `CI_ENV_MODE=production` for live deployments. Never set a production stack to `development` merely to debug
it; use a separate development deployment and reproduce the issue there.
