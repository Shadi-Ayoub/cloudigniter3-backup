`CI_ENV_MODE` is runtime context. Core tenant records do not store an `envMode` field and CloudIgniter does not
append a mode suffix to PK or SK values. Canonical keys remain capability-oriented, for example:

```text
PK = CI#SYSTEM#TENANT#dev-acme-school
SK = CI#META
```

Use separate Amplify deployments and their generated physical tables to isolate development, test, staging, and
production data. Within each table, build every key with `ciBuildTableKey()` or `ciBuildTableKeys()` and enforce
the normal tenant and authorization boundary.

Development seeding adds explicit provenance to each created record and an atomic marker in the same bounded
context. Cleanup queries the marker partition; it does not search for an environment suffix or scan the table.
