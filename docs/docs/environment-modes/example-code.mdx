    - question: "How do the mode recipes keep development behavior outside production operations?"
      answer: "Use ciCanAccessDeveloperTools with the resolved mode and authenticated actor's exact roles, then repeat the check at mutation and provider boundaries. Ordinary production behavior continues without those capabilities; UI visibility alone never enables development operations."
    - question: "Where should an example resolve server environment values before exposing safe client behavior?"
      answer: "Resolve the mode and authenticated identity during server bootstrap or the operation's trusted context resolution. Pass only the resulting safe presentation state to the browser, and resolve fresh server/provider inputs again when the user invokes a mutation."

```ts
import { ciCanAccessDeveloperTools } from "@cloudigniter/core/lib";

const allowed = ciCanAccessDeveloperTools({
  envMode: context.env.mode,
  actor: {
    authenticated: context.auth.user.authenticated,
    roles: context.auth.user.roles,
  },
});
```

Use the result to compose presentation. A mutation must call the same helper again with fresh trusted context,
and the provider handler must independently require `CI_ENV_MODE === "development"` plus exact Cognito group
membership.

Do not branch authorization on `process.env.NEXT_PUBLIC_CI_ENV_MODE`; that value is delivered to the browser and
is not trustworthy evidence.
