# Testing goals

A feature's verification should cover:

- successful behavior with the intended actor and scope;
- denial for missing identity, wrong permissions, and another Tenant's data;
- validation failures and provider failures without misleading success UI;
- deterministic fixture ownership, retries, and cleanup;
- direct navigation, translations, accessibility, and narrow-screen behavior.

Use an explicitly disposable deployment for integration tests. Keep production credentials and resources outside
that test configuration. See the [testing strategy](/docs/testing-strategy) for the complete sequence.
