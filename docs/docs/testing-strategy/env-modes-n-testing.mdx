CloudIgniter supports `development`, `test`, `staging`, and `production` modes. Automated tests may use `test`
as ordinary runtime context, but deployed Dev Beacon, Debug Probe, and seeder mutations require `development`
plus an authenticated actor with exact `developer` membership.

Environment isolation comes from separate deployments and resources. CloudIgniter does not suffix PK or SK values
with a mode. Tests and fixtures must use the canonical key builders and the same bounded-context access patterns
as production code.

See [Environment modes](../environment-modes/intro) and
[Development tools and application seeding](../environment-modes/development-tools-and-seeding).
