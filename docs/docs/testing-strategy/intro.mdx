# Testing foundations

Use separate development, test, staging, and production deployments. Tests should exercise the same validation,
permission checks, provider adapters, and key conventions as ordinary application behavior. An environment label
alone does not isolate data or grant access to developer tools.

Begin with [Testing goals](./testing-goals), then follow the [testing strategy](/docs/testing-strategy).
Use [development seeders](/docs/environment-modes/development-tools-and-seeding) only in their supported
mode with an authenticated developer and explicit fixture ownership.
