I want to describe the layout of page rendering architecture in cloudigniter in the cloudigniter-development architecture.

One step that is being used by the root layout, internal layouts, and page components is what I call "bootstrapping" which resolves the corresponding context needed to pass to the corresponding wrappers.

The root layout bootstrap via the helper apps/template/src/kernel/server/root/appResolveRootLayoutContext.ts which provides the resolved properties for the <html> and <body> tags. and also uses the component apps/template/src/kernel/server/root/AppRootWrapper.tsx that provides the <NextIntlClientProvider> provider and the <DevBeacon> component to children components.

The root page and internal layout components bootstrap via apps/template/src/kernel/server/bootstrap/app-bootstrap.ts to resolve the system context.

Internal layout components pass the context to <CiLayout> that provide the skeleton of the HTML page with the layout structure components like the header, Container, and the footer after wrapping the structure with the theme provider, debug prob provider, AntdRegistry provider. It also adds the <CiFeedbackProvider> and <CiInitialLoader> components inside the wrapping providers with the children. Using <CiLayout> guarantee a consistent behaviour for all pages as well as guarantee the availability of the system capabilities to all pages.

internal pages pass the resolved context to <CiPage> which wraps the page content with the page content structure and scrolling capability as well as wrapping the content with the <NextIntlClientProvider> provider again after the layout doing the same.

// CiDataTable
Implement a component that can be imported from @cloudigniter/ui based on TanStack table (see https://tanstack.com/table/latest and https://github.com/TanStack/table) to be used by the template application and Cloudigniter's users to list and manage objects like users, tenants, etc. consider the following capabilities of the component:
- Allows selecting different formats having the simple table as the default.
- Allows defining the columns with their names.
- Allows defining the actions per row. It can offer three modes. List of icons/buttons to be displayed as the last field in each row (left-most for LTR and right-most for RTL), a drop-down menu, or a mix of horizontally aligned icons/buttons having the last one as the drop-down menu button/icon. The callback of each icon/button action is part of the definition.
- Allows enabling the option of sorting per selected column. The sorting criteria and direction is part of the definition with a default criteria.
- Allows enabling filtering the table based on the filter of the corresponding column.
- Allows rows to be selected if table global actions and filters are defined for the table component.
- Allows cell clicking (specified fields) to open a model or direct to another page.
- Supports paging to list per page. The size of each page can also be decided via a drop-down button. The option to list "All" needs to be controlled for large tables.
- Allows defining global action buttons at the top of the table to apply certain actions on the selected rows. A global action button can also perform a general action independent of any selection like for example generating an Excel report.
- Allows defining drop-down filters to list items based on the selected filter criteria.
- Works seamlessly with handlers that connects with the provider database/tables.
- Allows controlling values displayed in cells like truncating large text shown in the table cells.
- Provides out-of-the-box global action buttons like exporting the current table (considering active filters and sorting) into a downloadable Excel file.
- Highlights the row upon mouse hover. This feature can be disabled within the component configuration.
- Alternate background colour for rows by default (odd rows has a colour and even rows have a different colour. The table header has its own formatting like a dedicated background colour and text boldness strength)
- Allow defining certain formats for selected columns cells value like making them bold or have a value displayed in a certain format (CSS class) based on a condition which can be a callback that returns a boolean value!
- Takes the full container width by default utilising Flex rules to layout the columns. However, table width can be defined as a fixed number or a percentage.
- Allows enabling columns width adjustment by the mouse to, for example, reveal truncated text.
- Uses a cookie in the browser to retain the last adjustments by the page user like columns adjusted width, the last selected filter and page size.

Provide all the needed helpers that can be imported to define/configure the table and connect to the data source using a defined structure for the component. So, we have the data, definition, and configuration. I am open to the best way to implement the component using the best practices out there.
